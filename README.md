# Workflow

通用 agent skill 集合，用于需求整理、实现、调查、审查和验证。具体技术栈、架构边界与检查命令从目标仓库读取，遵循当前任务授权和该仓库的 `AGENTS.md`。

## 选择 skill

| Skill | 适用请求 | 主要产出 |
| --- | --- | --- |
| [to-spec](skills/to-spec/SKILL.md) | 将已有讨论整理为需求规格 | 目标、范围、验收条件、实现决策与未决事项 |
| [to-issue](skills/to-issue/SKILL.md) | 整理问题草稿或明确要求建立工单 | 证据、复现或调查假设、验收条件与交接说明 |
| [feature-dev](skills/feature-dev/SKILL.md) | 实现功能或修复已授权的问题 | 按风险分级的方案、实现、回归与验证结果 |
| [tdd](skills/tdd/SKILL.md) | 先测试后实现，或为 bug 建立回归用例 | 修复前失败、修复后通过的行为证据 |
| [repo-migration](skills/repo-migration/SKILL.md) | 迁移系统或重构到明确的新架构 | 行为与目标对照、分阶段迁移和核验记录 |
| [pr-review-loop](skills/pr-review-loop/SKILL.md) | 审查 PR 或本地差异，按授权修复和复查 | 有证据的问题、逐条处置和最终审查结论 |
| [verify-harness](skills/verify-harness/SKILL.md) | 系统性验证功能，建立或维护验证装置 | 可重放的行为证据、功能到用例映射与装置文档 |
| [how](skills/how/SKILL.md) | 解释当前实现、运行流程或代码归属 | 有源码依据的调用流程、状态变化和边界说明 |
| [why](skills/why/SKILL.md) | 调查设计理由、历史取舍或阈值来源 | 已证实理由、合理推断及仍未知的部分 |
| [unslop](skills/unslop/SKILL.md) | 精简文档、报告或其他文字 | 保留事实和术语、表达直接的文本 |

按请求选择必要的 skill，不要求任务走完整流水线。已有清楚的需求可以直接实现；普通测试不必启动系统性验证；局部审查不必创建 PR；修复一个 bug 不等于迁移架构。

## 组合方式

- 需要整理需求时先用 `to-spec`，实现时进入 `feature-dev`。规格已充分时直接复用，不重新访谈或起草平行方案。
- `to-issue` 交接问题定义和已有证据。接手实现时重放相关复现，复用已确认的决定，不重复询问。
- `tdd` 处理具体的行为测试与修复循环；`verify-harness` 处理跨边界行为、真实交付物和验证装置。已有测试入口优先复用。
- 明确的架构迁移使用 `repo-migration`，按已确认目标区分应保留的行为和应纠正的缺陷。
- `pr-review-loop` 可以审查本地差异。只有本次任务已授权修复，才修改代码；只有已授权发布，才推送、建 PR 或回写外部系统。
- `how` 回答现在怎样运行，`why` 调查为什么这样设计。当前实现可以直接核实，历史动机需要证据支持。

这些组合是可选的。技能可以独立使用；缺少相邻 skill 时，不因流程名称中断已授权任务。

## 目录结构

```text
skills/<skill-name>/
├── SKILL.md          工作流与触发条件
├── references/       按具体阶段加载的细则和模板
├── agents/           可选的宿主配置
├── evals/            可选的行为评估与最小夹具
└── LICENSE           引入上游内容时保留的许可
```

每个技能目录应完整携带所需引用。项目分发使用实际文件，不依赖仓库外的个人绝对路径。个人本机使用软链接时，链接目标需保持可访问，编辑链接也会修改源文件。

## 调用与授权

`tdd`、`unslop`、`how`、`why` 和 `to-spec` 保留来源技能的显式调用策略，通过 `agents/openai.yaml` 表达 Codex 的调用策略。其余技能保留基于描述的自动匹配，描述只覆盖各自职责。

技能被发现或选中只决定采用哪套方法，不增加任务权限。建立工单、发表评论、推送、创建 PR、合并、部署和运行有费用的真实服务，均须在当前已授权范围内；用户没有回应不构成授权。已有明确授权不重复确认。

只读调查与审查保持只读。无法访问历史、CI、外部系统或运行环境时，说明缺失的证据，并继续完成可以核实的部分，不把未运行的检查写成通过。

## 维护约定

- `SKILL.md` 保留目的、范围、执行骨架和参考入口，详细方法按需放入 `references/`。不重复抄写项目的架构规范、脚本或覆盖率阈值。
- 描述应简短且能区分相邻技能，避免将普通开发、单测、解释或审查都路由到完整迁移与发布流程。
- 使用当前宿主实际提供的工具；委派任务默认继承当前模型，不依赖固定厂商型号或其他宿主的专用工具名。
- 改变流程时同步检查入口、参考材料、模板及评估场景，避免主文档与细则给出相反指令。
- 技能校验验证结构；行为评估验证决策。使用最小、隔离的真实场景检验路由、证据质量和权限边界，不用匹配文案代替行为验证。
