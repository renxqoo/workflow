# 多轮审查、修复与有限复查

一次日常只读代码审查优先使用 `code-review`；本技能负责用户明确要求的审查循环。用户直接调用本技能但仅要求审查时，按下文只读模式完成，不自动修复。

验证改动是否实现本次要求，并找出可证实的缺陷。空审查是合法结果，不为凑数制造 finding；审查通过只描述实际检查过的范围和版本。

## 1. 确定模式、范围和能力

- **只读审查**：用户只要求 review、审 PR 或指出问题时，读取改动和上下文，输出发现与验证限制，不修改产品、提交或外部内容。
- **修复与复查**：只有用户明确要求修复审查发现、反复审到完成或等价任务时，才在本次授权范围内进入循环。已获授权无需重复询问；任务外问题单独报告。
- **审查对象**：已有 PR 可读 PR diff；无 PR 时审本地已提交、暂存或未暂存改动。先看状态并确定基准，不能因无 PR 强行建分支或发布。对象不明确且会改变审查范围时再澄清。
- **操作权限**：本地修复、commit、push、创建 PR、回写 PR/评论是不同动作，分别核对已有授权和目标仓库规则。审查或修复请求本身不授权后续发布动作；不自动合并或部署。

读取目标仓库的 AGENTS、实际脚本、测试配置和 CI，确定本次需要的验证命令、运行环境与门禁。没有统一的框架、运行时、覆盖率数字或四门清单；不猜命令，不降低原门禁。只读审查无需先跑完整流水线；修复后按目标项目要求验证最终改动。

使用可用工具读取 Git/PR 和派发审查者。没有 PR 工具则审本地版本；没有子 agent 则串行自审并说明缺少独立上下文；使用新审查者时重放原 finding 与证据。启用 `task-orchestrator` 或用户明确要求全新上下文时，每次审查、修复和复查均新建代理；其余情况可按复查模板保留原审查上下文。无需指定模型，按当前环境能力工作。

## 2. 固定审查版本并按风险分路

记录仓库绝对路径、基准提交、被审提交或工作区状态，以及 diff 的范围。具体取 diff 和工作区版本记录方式见 [审查者模板](references/reviewer-prompt.md)。修复或外部改动改变相关文件时，旧结论不得直接沿用。

正确性审查参考 [正确性章程](references/rubric-correctness.md)。需要专门审查的风险面参考 [风险路章程](references/rubric-risk-lanes.md)，例如 UI、并发、消费方契约、安全、可用性或性能。小改动单路足够；中高风险按实际需要增加独立路，不为没有命中的风险组路。

多路采用互补范围或方法：静态追踪、已有失败用例复跑、真实运行观察。共用模型的多路结果不是独立保证；同报只是优先核实信号。每路只读，只提供对应章程和足够背景；代码修改集中在实现方，避免共享工作区互相覆盖。

## 3. 输出只读审查或进入修复循环

只读模式：核实发现，按严重程度给出位置、触发条件、具体后果和证据；无发现则明确说无发现，同时列出未运行的验证或不可见范围，然后结束。

修复模式逐轮执行：

1. 核对基准和被审版本是否变化，必要时重取 diff，仅重开受影响审查路。
2. 汇总去重，依 [处置框架](references/lead-judgment.md) 将 finding 归为修复、范围内低成本修正、记录未修或驳回。冲突先补证据，涉及目标选择的分歧再请用户裁决。
3. 仅修改已授权范围，优先消除已证实根因，采用最小充分改动。bug 回归用例应证明缺陷存在时失败、修复后通过；无法取得修复前证据时如实说明。不把每种结构建议都变成测试。
4. 按目标项目规则运行相关检查和要求的最终门禁，记录命令、结果及适用数字。未通过或未执行不能声称全绿；不通过 skip、删断言或改阈值规避失败。
5. 在同一个确切本地版本或已获授权的远端版本上复查，使用 [复查模板](references/recheck-template.md)。**不需要先 commit 或 push**；是否执行这些动作取决于独立授权。零改动轮也可复查处置理由。
6. 复查只核实原发现的处置和修复引入的回归。新的实质问题记录证据，按剩余范围和预算决定是否加一轮，不无限追加审查面。

默认最多 5 轮，按任务大小可更少；用户另有轮次或预算要求时遵从。全部相关审查路明确通过且必要验证完成时收口。某路没有回复、超时或未检查当前版本，记为未确认；可恢复或换审查者，**沉默不是通过**。

轮次耗尽或连续两轮没有有效进展时停止扩展，报告残留证据、系统性修复问题/审查标准漂移/真实复杂度等原因和下一步。不将停滞称为收敛通过，也不自动建票或发布。

## 4. 收口与可选外部动作

报告与任务规模相称，至少包含：

- 审查对象与准确版本、模式及覆盖范围；
- 发现/处置结果，各路实际结论与未确认项；
- 已执行验证及真实结果，未执行检查和环境限制；
- 剩余风险与完成状态。

若已有 PR 且读取 CI 可行，区分本地结果、远端版本的 CI 结果和 owner 审批。没有查到的 CI 记为未验证；本地工作区结果不能冒充远端 CI 通过。缺少必需的人审或门禁时，结论只到可交下一步，不能承诺可安全合并。

仅在用户已授权对应动作且目标仓库允许时才提交、推送、建 PR 或回写台账；外部更新内容必须基于本次确切版本和真实结果。未经授权的操作保留为可交付报告，不阻碍已授权的本地工作完成。合并与部署不属于本 skill。
