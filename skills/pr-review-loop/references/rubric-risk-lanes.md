# 按实际风险选审查路

此表用于选择额外视角，不要求每类都组路。小改动由正确性路覆盖即可；风险相近的面可以合并，单路发现新风险时先核实再决定是否增加审查者。

| 实际改动 | 可选专路 |
| --- | --- |
| UI结构、交互状态、主题或响应式 | UI与前端体验 |
| 事务、缓存失效、后台任务、共享状态 | 并发与一致性 |
| 被其他调用方依赖的接口、数据/schema或事件 | 消费方契约 |
| 认证、权限、加密、不可信输入到敏感操作 | 安全 |
| 外部依赖、迁移、运行配置、失败恢复 | 运行可用性 |
| 热路径、算法复杂度、数据量级 | 性能与量级 |
| 确有边界/结构变化且需要独立视角 | 可维护性 |

路数由风险、预算和可用能力决定。纯文案、小样式、私有重命名不自动组额外路。多个审查者用互补方法或范围，同报仅是核实信号，不按模型数量或票数裁决。仅将对应节交给该路，避免重复清单。

## UI与前端体验

检查实际适用的设计系统、亮暗主题、窄屏/RTL、长文本、加载/空态、错误反馈、键盘/可访问名和焦点。若有服务端渲染，核实浏览器 API、随机/时间/locale 造成的边界和水合差异。

视觉发现应给具体状态、平台、对比依据和可观察后果；无法运行时说明静态判断。项目没有某种主题/平台要求时不凭空新增要求。

## 并发与一致性

检查相关写入的原子性、check-then-act、缓存与源数据的一致性、重复触发/重试、部分失败、顺序依赖。对有效发现给具体交错和结果，不只说“可能有竞态”。利用现有可控时序/隔离测试，不在共享环境做未授权压力或破坏性验证。

## 消费方契约

追踪接口签名、字段/单位/时区/错误语义、事件和数据迁移的真实消费方，包括配置驱动和跨仓库已声明依赖。按项目明确迁移要求判断兼容性，不能一律要求双轨，也不能一律删除外部兼容层。说明受影响消费方和破坏条件；目标已授权变更时核对配套更新是否齐全。

## 安全

核实资产、信任边界和实际攻击输入到敏感操作的路径，关注授权、凭证泄露、注入、反序列化、SSRF、重放和安全关键竞态。给路径或具体缺失的防护及后果，不用无限猜测代替证据。动态探测只在本次允许的隔离目标内运行。

## 运行可用性

检查外部依赖超时/重试上限、取消和清理、失败反馈、迁移/恢复、资源边界。日志不是唯一可观测方式：已有结构化错误、指标或上层反馈可能足够。静默错误确实让目标失败不可见时说明路径和后果，不把每个 catch 都定为 blocker。

## 性能与量级

关注热路径循环内 IO、复杂度、无界增长、数据规模与阻塞。给实际调用频次、规模或测量依据，不报告没有业务意义的微优化。测试性能需要项目已有基准方法或明确任务，不能从静态审查扩展为无预算压测。

## 可维护性

核实实际层次/归属、公开边界、重复事实、接口复杂度和当前阅读负担。单文件行数和拆分规则以目标项目为准。结构建议要能说明具体成本；没有阻碍正确性的证据，不因个人风格要求增加层次、class、抽象或删除可用实现。
