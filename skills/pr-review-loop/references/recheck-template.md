# 同一确切版本的复查

启用 `task-orchestrator` 或用户要求全新上下文时，创建全新审查者；其余情况可优先找原审查者。使用新审查者时提供原 finding、证据、处置和当前准确版本，不能以恢复旧会话替代本次全新上下文要求。复查不要求先提交或推送。

```text
复查请求：第 {N} 轮

仓库：{绝对路径}
原审查范围：{范围}
当前准确版本：{提交SHA，或HEAD/index/工作区内容校验记录}
读取方式：{当前本地diff命令与未跟踪文件，或已授权取得的远端确切版本}
本轮改动：{有改动/无代码改动，仅请求核实处置}

已修：
- {原finding}：{改法、位置、回归证据和最终验证结果}

记录未修：
- {原finding}：{范围/环境/产品理由与剩余风险}

驳回：
- {原finding}：{原判断不成立的具体证据}

请核实原问题是否已解决、处置理由是否成立，以及本轮修复是否引入相关回归。不展开无关新审查面。新的实质问题应给证据，不能仅作附注后仍称通过。

请显式返回“通过”或“不通过/未能复查 + 理由”，并逐条说明对记录未修、驳回项的判断。整体通过可以明确覆盖全部列出的处置；未回复、未检查当前版本或未覆盖的项不能当作已同意。
```

## 发送与失效规则

- 先按目标项目要求完成本轮验证，再对同一个当前版本发复查；失败/未执行项一并说明，不能先说全绿。
- commit、push、PR 更新仅在各自授权内执行。审本地文件时给可核验的内容记录，无需远端同步；远端 CI 只对应其确切远端提交。
- 零改动轮也可核实未修/驳回理由，不为拿结论制造提交。
- 每路独立确认。后续改动波及已通过路时，仅重新检查受影响范围。
- 期限内无响应记为未确认，可换可用审查者重放证据，或在预算结束时报告缺口。沉默不是通过。
