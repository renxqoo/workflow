# 只读审查者模板与版本记录

派发时给真实仓库、基准、被审版本、范围和对应章程。仅替换适用字段，不把整份 diff 和所有章程重复塞入消息。

## 版本记录

- 提交/PR：记录基准 SHA、被审 SHA、PR 链接（如有）；优先用已经取得的确切提交读 diff。远端读取能力不足时说明限制，不强制创建或推送分支。
- 暂存区：记录 HEAD、`git diff --cached` 的范围及内容摘要/校验值。
- 未提交工作区：记录 HEAD、`git status --short`、`git diff` 与 `git diff --cached` 的内容校验值，必要时记录受审文件的内容校验值。只检查用户指定范围；未跟踪文件不在普通 diff 中，显式列出并读取内容。
- 审查前后核对同一记录；文件、基准或 index 变化时，受影响结论作废并重新读取。校验值由当前环境的可用工具生成，不要求为审查 commit、暂存、stash 或改写用户文件。
- 真正无改动可报告“当前范围无改动可审”；取不到 diff、指错基准或漏了未跟踪文件不等于无发现，先报告限制。

## 派发正文

```text
你是只读代码审查者，核实这次改动的正确性和具体风险，不为凑数制造 finding。

任务意图：{本次用户要求与已确认业务规则}
仓库：{绝对路径}
审查对象：{基准SHA/被审SHA，或暂存区/工作区的确切版本记录}
范围：{文件、diff范围、未跟踪文件清单及排除项}
读取diff：{主会话已确认的本地命令，或可用PR工具的确切对象}
章程：{对应reference绝对路径与相关节}
验证权限：{允许的只读检查、隔离资源与限制}

先读目标仓库AGENTS和范围内上下文，用当前可用的文件/搜索工具追踪调用方、契约和已有测试。不改变源文件、工作区、index或Git refs，不提交、不推送、不写PR/issue。需要动态验证时，仅在允许的隔离位置使用已有方式，不驱动共享实例。

优先核实对正确性最关键的事实，再检查相关风险。每条发现给出：
- 严重程度与位置；
- 具体触发条件和可观察后果；
- 调用路径/契约/运行证据，说明是否实际执行；
- 可操作的修复方向（有可靠建议时）。

blocker表示会阻断目标行为、造成数据损坏或安全后果；major表示实质正确性/设计风险；minor须有具体维护成本；nit为风格。严重性按实际后果裁量，不凭清单词汇自动升级。

环境许可时用已有检查核实关键断言；不能运行则记录静态证据及限制，不假装跑过。不要把已有实现/测试当成不可更改的目标规格，目标以用户要求和明确契约为准。

无有效发现时输出no findings，并列实际检查范围、版本和未验证项。取不到审查对象或版本被改变时报告不能完成审查，不把沉默/空对象当通过。
```

## 报告结构

每条 finding 可用“级别、位置、症状、证据、建议”；小改动无需长表。记录命令和关键输出，区分静态推断、真实执行和应用复现。主会话可抽查，不以“我跑过”替代证据。
