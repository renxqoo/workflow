# StoreDesk

这是一个用于方案讨论的虚构业务快照，所有文件都是原始设计材料，没有可启动服务。当前由四名工程师维护，在单一区域部署。

## 业务与现状

- 商家按租户使用后台创建订单、查询订单和导出筛选结果。每天约 1200 张订单，记录中的高峰为每秒 15 个 API 请求；没有未来容量承诺。
- 当前只有一个 Python API 部署和一个 PostgreSQL 实例。部署说明没有后台 worker、消息代理或分布式缓存。
- 创建订单由 orders 包完成。通知在创建流程中调用外部通知供应商；供应商慢时订单响应也会变慢。
- 导出在 API 进程内执行，数据较多时一次请求可能持续约 20 秒。用户离开页面后不能查询任务进展，失败后只能重新点导出。
- orders 与 exports 都包含筛选规则，新增筛选条件时经常只更新一处。

## 本次产品目标

- 下单成功不取决于通知供应商即时可用；通知可以延迟，但应能看到失败并进行后续处理。
- 导出继续复用用户的筛选条件，用户可以离开页面后查看进展、获取结果或看到失败原因。
- 导出只能包含该商家被授权查看的数据。当前筛选与金额规则保持不变。
- 运维团队能维护 API 和少量后台进程。独立部署与引入基础组件需要明确收益和迁移成本。

是否需要按请求时点固定导出数据尚未决定。现有导出结果按执行时查询，不应把任何新的快照语义当成已确认要求。
