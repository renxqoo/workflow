# Checkout 服务材料

这是虚构业务的当前契约与存储草图，用于服务端方案讨论，没有支付凭证或可运行服务。

## 已有条件

- 服务使用 PostgreSQL、现有 HTTP API 和后台任务执行进程，本次继续使用它们。
- 认证中间件提供 tenant_id 与 user_id。客户端可以提供商品和数量，金额与币种由服务端可信商品数据确定。
- 创建订单接口已有 request_key 字段，当前存储草图没有相关唯一约束或请求结果记录。
- 用户可以在支付确认前取消订单。取消成功后不再履约；若后来证实已扣款，需要退款或进入可追踪的对账处理，不能丢弃扣款事实。
- 通道支付结果会通过回调返回，服务也可以主动查询。库存不是本次范围。
- 当前业务要求同一租户的同一创建意图只生成一张订单，相同意图的重试能找到原订单。

## 待设计的协作

创建订单、发起支付、取消订单和支付回调之间会并发或遇到超时。请根据请求范围细化接口、数据与事务步骤；尚未确认的通道保证见 payments.md。
