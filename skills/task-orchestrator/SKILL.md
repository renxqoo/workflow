# 任务拆分与全新代理编排

协调者维护目标、依赖、版本与验收，每个执行任务交给全新上下文的子代理。拆分不替代领域设计、开发、测试或审查方法，也不扩大当前任务的写入与发布范围。

## 1. 确定模式和起点

- **只拆分**：用户只要计划时，交付任务及依赖，不派发实现者、不修改产品。
- **拆分并执行**：用户要求委派实施时，建立任务图并推进至验收；已有规格或计划直接复用，只修正有证据的缺口。
- 读取适用的 AGENTS、工作区状态、相关实现、现有计划及实际检查命令，记录需保留的在途改动。先区分用户目标、已确认决定、代理选择与阻塞项，不重新访谈已确定内容。
- 核实当前宿主能否创建独立子代理并关闭父会话继承。无法保证全新上下文时交付计划和能力限制，执行状态保持未完成，不在主会话代做后声称已委派。

小任务用简短列表；多阶段或需要恢复时沿用项目计划位置记录，缺少约定可保存一份本地任务计划。不得为规划默认 commit、push、发布工单或接入外部进度平台。

## 2. 拆成可验证的依赖任务

按 [任务计划](references/task-plan.md) 写稳定编号、交付结果、依赖、输入位置、写入范围及验收方式。任务应足以在一个新上下文完成，避免只按技术层切成无法独立验证的大块；机械迁移按实际依赖和切换条件分批。

检查需求是否有对应任务、依赖是否存在且无循环、共享契约是否先确定。不要为了并行凑任务数，也不把“阅读代码”“再阅读一次”独立成没有产出的任务。

默认串行执行依赖已核验的就绪任务。同一目录或共享资源只能有一个实现者写入。确有并行收益且能提供独立工作区、明确所有权和集成办法时，再按 [核验与集成](references/verification-and-integration.md) 并行；没有隔离条件则串行。

## 3. 每次派发都新建上下文

每个任务、修复、重试和独立复查均创建新的子代理，默认继承当前模型。**继承模型不等于继承对话**：核对实际工具的上下文选项；若提供 `fork_turns`，使用 `none`。新代理 ID 本身不能证明没有继承父会话。

按 [派发与回报契约](references/delegation.md) 提供自足 brief：原始目标、本次任务、已确认约束、当前版本、必要材料与前序结果的位置、允许写入范围、验证入口、完成条件及返回内容。只传任务需要的信息，不把完整聊天、全部规范或前序推理复制进去。

已返回的代理不接下一任务，也不通过 resume、follow-up 或恢复旧会话承担修复与重试；新代理取得合并后的原任务、后续指令及已观察结果。在途澄清、停止和取消可以给当前代理发消息，不能借此给已结束任务续派新工作。

协调者控制所有派发。子代理不自行再拆分或创建代理，除非本次 brief 明确允许并分配资源。一次实现任务只负责其范围；独立审查若有必要，由另一名全新只读代理承担，不把实现者自查称为独立审查。

## 4. 核验后推进，失败交给新代理

收到回报先读取实际产物、diff 和相关检查结果，按 [核验与集成](references/verification-and-integration.md) 核对版本、验收和写入范围。代理说完成只表示待核验；依赖任务通过协调者核验后，下游才就绪。

发现范围内缺陷时，以准确复现、当前文件/分支和原任务为输入派发全新修复代理。缺材料或环境阻塞先区分原因，不盲重跑；不能把缺证据、超时或无回复当通过。

用户预算优先。没有约定时，每项任务默认初次执行加最多两次修复/重试；同一阻塞重复且无新证据时提前收束。受阻任务及依赖保留未完成，继续独立可做的任务，不降低验收条件或无限扩大任务图。

相邻技能允许复用旧会话时，本次全新上下文要求仍适用于所有编排中的派发。多轮审查只在明确需要时使用，遵循本次更严格的尝试与资源预算。

## 5. 集成与收口

在最终交付版本上核对每项目标的完成证据及项目要求的检查。并行任务的分支结果不能直接充当集成结果；串行执行也要核实后续改动是否使前序结论失效。

报告已核验、受阻和未执行任务，实际使用的代理及尝试、最终版本、验证与遗留项。仅清理本次持有且已安全交付的资源，保留未集成成果和证据。用户要求停止时结束新派发，协调在途任务到安全边界，并记录准确恢复点。

## 与相邻技能的分工

- `feature-dev`、`repo-migration` 提供实现或迁移方法，`architecture-design`、`backend-design` 提供确有需要的设计；本技能只管理任务与执行，不重新发明这些流程。
- `test`、`code-review` 和 `verify-harness` 仅在任务需要时提供相应方法，不让每张任务走完整流水线；显式调用策略仍按宿主和用户选择执行。
- `to-issue`、`lark-project-progress` 负责已授权的工单或进度同步，不能以发布状态代替本地验收。相邻技能不可用时按任务契约完成能做的部分，不先强制安装它们。
