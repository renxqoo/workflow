# 核验、集成与资源所有权

执行者回报后，协调者对最终交付负责。委派报告是检查入口，实际文件、版本与行为证据才是推进依据。

## 默认串行

同一已确认工作区中，一次只有一名实现者写入；协调者在其执行时不改同一产品范围。执行者结束后检查 diff、未跟踪文件与验收结果，必要时用已有命令定向复验；通过后才派发下个全新代理。

保留用户及前序任务的修改，不为取得干净基准而 reset、stash、暂存或提交。串行不要求每个任务提交；用文件内容摘要、diff、index 状态及产物记录传递准确版本。

## 并行的前提

写入任务仅在互不阻塞、所有权明确且工作区/资源可隔离时并行。给每项独立 worktree/分支或产物位置，端口、数据、缓存与外部资源也要隔离。文件不同不代表不会争用共同 schema 或运行实例。

从已核验的集成版本创建执行基准，原工作区有在途修改时说明它们怎样进入该基准，不能默默忽略。协调者是唯一集成写入者，记录实际基准和被集成产物。没有获准的提交操作时，用已核对的补丁或产物集成；需要提交的工具路径不能把该需要自行转换为授权。

结果过期、有冲突或碰到他人在途区域时先核实，并将范围内集成修复交给全新代理。集成后的结果仍需验收，不能拿各分支单独通过替代集成验证。

## 核验内容

1. 实际产物存在且对应正确任务与版本；来源不只是报告中的链接或截图描述。
2. 改动在授权和分配范围内，没有覆盖原有修改或私自调整门禁。
3. 验收行为与独立预期相符，检查覆盖真实消费入口；bug 的红绿证据与普通契约测试分别判断。
4. 已运行与未运行、静态推断与实测清楚；失败或缺少必需检查仍是未完成。
5. 必要独立审查由另一全新只读代理完成，相关结论针对同一确切版本。

优先读取原始输出与产物，只在新变化、结果冲突、证据不充分或项目要求时重跑检查，避免机械重复整套测试。任务级核验与最终项目门禁分别记录。

## 阻塞、停止与清理

缺依赖、环境、信息或权限时给实际条件及解除方式，保留成果。按预算用新代理修复或重试；同一阻塞无新证据时停止该路径，独立任务可继续。超时或丢失回报不能当作通过，也不能直接转交仍可能被写入的范围。

用户要求停止时不再派新任务，通知在途代理停止，记录其是否已终止、磁盘状态和恢复点。只回收本次创建且不含未集成成果的 worktree、进程与临时资源；不能删除他人的工作或将保留证据一并清理。

收口给已核验、受阻和未执行任务、实际代理及尝试、最终版本、门禁结果和资源状态。未完成目标不能被“所有代理已退出”替代。
