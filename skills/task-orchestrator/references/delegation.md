# 全新上下文派发与回报

用于每个实现、修复、重试及只读审查。使用当前真实可用的工具，默认继承模型，同时显式关闭父对话继承；工具没有该参数时核实它是否默认创建独立上下文。不能保证时报告限制。

## 派发正文

```text
原始目标与本轮授权：{用户要实现的行为，本次可做的动作与限制}
任务：{稳定ID，本次交付结果与非目标}
工作位置与准确版本：{仓库/工作区，提交或文件与index状态记录}
已确认约束：{相关项目规则、契约和决定的位置}
输入与前序成果：{规格、必要源码、已核验产物及回报位置}
允许写入：{文件/资源范围，已有在途修改及其保留要求}
验证与完成条件：{已核实命令、独立预期和必须得到的证据}
回报位置：{宿主回报或本次明确的产物目录}

仅完成本任务，不接管其他任务或自行创建代理。读取实际文件和适用AGENTS。
遇到缺少事实时先调查；目标冲突或范围外问题给证据，不擅自扩大修改。
返回实际改动、结果、运行命令及输出、版本和剩余问题；未运行不得写通过。
```

只填相关信息，不内联全部聊天和大段源码。新代理应能仅凭 brief 与指向的材料开工；前序报告不能替代关键事实核实。不得把密钥或无关私有材料塞入 brief。

## 修复与重试

新代理拿到原任务、全部适用后续指令、当前准确版本、前次改动/产物和已观察的失败。复现与修复方法由问题决定，不把协调者未证实的猜测当成指定答案。

如果前次进程仍在写入，先停止或等待其退出，再转交写入所有权。不能因超时立即让两个代理同时接管同一目录；未能确认退出时，该写入范围仍受阻。

停止、澄清和取消可以消息通知在途代理。同一代理返回后，下一工作必须重新创建；`resume`、follow-up 或同一会话的新一轮均不满足全新上下文要求。

## 回报契约

- 任务 ID、当前工作区/版本和实际改动或产物位置。
- 实际执行的命令、退出/结果、对应验收及未执行项，保留必要原始输出。
- 已完成、发现范围内问题或受阻；列具体症状与下一步所需条件。
- 仍在运行的进程和本次持有资源、尚未安全清理的成果。

协调者另行记录真实代理标识、启动时的上下文选项和尝试次序。记录用于审计派发，不凭代理自称 fresh 证明上下文隔离。
