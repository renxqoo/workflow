# 可恢复的任务计划

已有规格、设计或任务图作为输入，保持稳定编号与已接受决定。小范围可用列表，大范围沿用项目文档或任务系统，不要求特定格式或平台。

## 每项任务需要什么

| 内容 | 用途 |
| --- | --- |
| ID 与交付结果 | 能独立说明完成后得到什么，关联来源需求或验收项 |
| 依赖 | 真正决定可开工的任务 ID；注明依赖的契约或产物 |
| 输入 | 规格、决定、相关源码、前序产物与当前版本的位置 |
| 写入范围 | 允许改的文件、工作区或产物，以及需保留的在途改动 |
| 验收 | 独立预期、实际入口、适用检查与完成证据 |
| 状态与尝试 | 当前状态、实际代理标识、尝试次数、结果及阻塞 |

例如先修正金额边界并验证，再让 CLI 使用该行为输出 JSON；两项以消费者可观察结果划分。拆分方式取决于真实契约，不能对任何项目套用相同票据。

## 检查任务图

- 每项需求有交付或明确的待决原因；任务不是模糊的“做后端”“完善测试”。
- 依赖 ID 存在、无自依赖和循环。已有计划有环时先说明冲突，不能随意删边把任务标为就绪。
- 依赖按已核验的交付判定，而非仅凭代理退出或任务表显示完成。
- 同时改共享接口、schema 或配置的任务明确先后；声称文件不同仍须检查共享状态和消费关系。
- 记录各任务在哪个基准开始，以及执行后哪些文件/契约发生变化。下游读取的是已核验的最新产物，不是规划时的旧草图。

## 状态与推进

待执行 → 就绪 → 执行中 → 待核验 → 已核验。

核验不通过转待修复；新修复代理完成后重新待核验。环境、能力或真实待决项转受阻，保留原因、已做尝试与解除条件。取消、未执行和失败各自记录，不折算成已完成。

所有依赖已核验且本任务输入仍有效时才就绪。集成或后续改动影响已核验任务时，重新打开受影响的验收，不重跑无关内容。

## 恢复

保存原目标及范围、任务图、工作区与版本、产物位置、尝试与代理记录、已确认结果、在途进程/资源和下一步。已返回代理只留下记录，恢复仍派发全新上下文。

恢复先核对当前文件、index、分支与记录是否一致，保留新的用户改动。只重验发生变化或证据不足的结论；记录中的“有权限”不能替代当前指令和实际工具权限。计划位置与状态事实保持一处权威来源，外部任务表按已授权范围同步。
