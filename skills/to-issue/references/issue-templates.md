# 可独立接手的 issue 模板

按问题规模选轻量或完整结构，删除不适用节。模板用于草稿与已授权发布，不构成发布、修复或后续外部回写许可。

## 轻量问题

```markdown
# 标题：具体现象或需求

## 现状与证据
触发条件、期望/实际、环境和版本；bug标定位档位与可重放命令。

## 期望与验收
- 可独立验证的行为。

## 接手信息
已确认选择、限制和查重结论；无复现时说明怎样继续定位。
```

## 复杂问题

```markdown
# 标题

## 现状
用户可观察的问题、当前处理方式或具体维护成本。

## 目标
谁在什么场景要完成什么；依据本次要求和明确契约描述。

## 证据与定位
定位档位、来源、版本、触发条件、命令、关键输出；
静态假设附证据与证伪条件，未知项如实说明。

## 验收标准
- 可验证的外部行为或约束，不写“工作正常”。

## 范围与选择
本次边界，已确认事实/选择、待核实假设及必要待决项。

## 接手提示
先核对现状和复现条件；症状消失时说明新证据，不直接实施或关闭。
修复行为缺陷时保留回归证据；后续修复、状态回写、关联PR或关闭须遵守各自授权与仓库约定。

## 来源与查重
原始报告/审查来源，查过的关键词与对象，重复/复发判定和访问限制。
```

## 类型差异

- **bug**：描述确切症状，区分用户报告、静态推断和实际运行。档 2 给可重放证据；档 1 只列证据支持的假设，无条数要求；档 0 说明未定位与缺少的条件。验收覆盖目标行为和适用回归，不要求无行为变化的清理硬造失败测试。
- **feature**：用户故事、当前替代方式、目标行为与边界，记录真实影响面，不发明已存在的接口或服务。
- **tech-debt**：具体成本及为什么需要处理，验收体现可验证的约束或成本改善，不以个人品味代替问题。若意图保持行为不变，应写清可观察不变量。

## 引用与耐久性

行为、接口和契约是主要描述；源码证据可给带提交 SHA 的永久链接及必要位置，帮助接手方查证。浮动路径/行号不是验收规格，不能代替症状与触发条件。复现命令用仓库相对位置和已声明前置，不依赖个人绝对路径。

日志保留必要原文和来源，但先脱敏再落盘/发布。错误码、环境变量和接口名称只有确认定义后才引用；假设内容显式标记，不写成已有事实。

查重命中时，只有本次明确允许更新/补充已有工单才追加同一问题的新证据，不重复贴全正文。仅授权创建时交付已有链接、判定与补充草稿，不自行评论或重复建票；访问不了现有工单时说明限制。问题确需多个独立工单且在用户范围内时才拆分，明确依赖和各自验收，不套固定文件数或会话规模。

可用的实现/审查 skill 仅作可选指路，不在正文要求自动修复、固定 `Closes` 语法、自动评论或发布 PR；平台关联方式与关闭行为遵循目标项目实际约定。
