# 代码历史

用本地历史确定变更，再到可访问的 PR、评审和关联记录寻找当时的理由。git 和远端 CLI 都需核对可用性；浅克隆、重写历史和 squash 会造成缺口。

## 调查入口

根据问题选择命令，路径、符号与提交必须来自已核对的目标，不机械执行全部命令：

```sh
git log --follow --oneline -- <file>
git blame -L <start>,<end> -- <file>
git log -S '<exact-text>' -- <file>
git log -G '<pattern>' -- <file>
git show <commit> -- <file>
```

引入行为的提交通常比最后触碰该行的提交更有解释力。查看重命名之前的历史、同提交变动和前后修订，提取 PR 编号或工单线索。远端记录优先用当前可用的只读连接或已配置 CLI，核对仓库身份后阅读正文与评审。

仓库内的 ADR、测试名、断言、现有注释和发布记录可提供线索。代码说明机制；测试说明被锁定的行为；二者仍不能单独证明作者为什么选择它。

返回关键提交、变动内容、时间、相关 PR/工单引用及它们明确表达的理由。缺少远端记录或历史不完整时说明限制，不把它当成从未有过讨论。
