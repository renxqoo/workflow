# 产品与分析数据

适用于 Databricks、Snowflake、BigQuery 等。围绕阈值来源、实验、使用量或迁移问题才选择此类来源，不为查全系统而查询。

## 先发现，再查询

使用当前可用的只读接口，先核对实际表、字段、单位、时间列、事件定义和去重规则。表名、字段名、模型约定和刷新周期均由所在组织决定，不能照搬示例。异步查询返回任务 ID 时，使用接口支持的结果读取能力，不重复执行同一昂贵查询。

按变更日期与问题设定有限时间窗，优先已有可信模型和聚合统计，避免无界扫描及原始行输出。读取权限不代表可以修改表、调度任务或运行回填。

## 有用的调查方式

- 比较相关事件在变更前后的使用量，同时核对埋点自身是否改变。
- 查看变更前的数据分布、中位数或尾部值，判断是否与阈值有关。
- 核对实验曝光、分组和结果记录，寻找明确的决策说明。
- 检索相关查询历史、耗时与资源量，寻找性能重写或迁移线索。
- 查看数据模型依赖与模型仓库历史，解释上游变化；跨来源线索可交回主会话。

所有这些数值关系都需要与提交、PR 或决策记录结合，不能把时间相关性当成动机证明。事件量阶跃可能是埋点变化，零结果可能是保留期或模型创建日期导致，类型化模型也可能有刷新滞后。

返回实际表名、可复核查询、时间窗、数值摘要和相关性说明。某种接口无法读取 notebook 或历史模型时说明限制，不泛化为整个产品都不支持。
