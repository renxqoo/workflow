# 工单与需求记录

适用于 Linear、Jira、GitHub Issues 等。先检查实际连接的搜索、读取和评论接口，不假定固定工具名。

先读提交或 PR 关联的工单，再用业务词、符号、错误文本检索相关问题。父工单、项目说明、里程碑、评论和重复问题的原始记录，可能解释当前实现之外的业务推动因素。必要时沿关联文档继续调查或交回主会话协调。

有力证据是具体的需求原因、被否决方案和带理由的裁决。标签与截止日期只是线索，不能单独证明动机。“提升体验”等模板文字不足以解释某个具体设计。

核对时间与范围变化、关闭后重开的历史、重复问题链，以及最后实现是否符合原计划。不可访问时记录权限限制。

返回工单编号、标题、URL、相关正文或评论的精确位置，以及有记录的作者与时间。区分提出的要求、达成的裁决和最后实现，不把某一阶段的计划直接当成现状。
