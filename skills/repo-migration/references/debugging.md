# 迁移集成缺陷定位

以当前行为证据与已确认目标定位偏差，不以“旧测试通过”或“新测试通过”单独证明迁移正确。

## 固定证据

记录触发输入、迁移单元、运行形态、等待位置、部分输出及最后一个已确认副作用。区分调用未发出、对端未回、数据已到但没有被消费，必要时采集栈或任务信息。

比较单独运行与相关组合运行，排查隔离、并发顺序和共享缓存污染。定位可暂时缩小输入或收紧本地超时，但不能把这些旋钮改为门禁的掩盖措施；相关变更仍服从项目约束。

## 缩小根因

沿实际入口、编排、模块和外部依赖逐层验证契约，找到首次偏离目标的地方。怀疑运行时语义时创建最小复现，先排除用例本身的错误假设；必要且获准时再做运行时交叉验证。

按症状核查：

- 流式消费、背压、分叉与取消的等待关系，不能将所有未完成写入判为死锁。
- 连接池、重试与资源预算造成的排队、重复副作用或清理遗漏。
- 开发与构建产物的解析条件、依赖闭包、配置与静态资源差异。
- 数据迁移、消费者切换和晚到任务是否仍引用旧接口或旧形态。

这些是调查方向，不预设具体修法。根因可能位于旧实现、新实现或验证装置；按目标与证据归类，不能为保持旧行为掩盖旧缺陷，也不能为实现换绿弱化断言。

## 修复与验证

在授权范围内做最小充分根因修复，补症状回归并取得修复前失败与修复后通过证据；无法取得时说明原因。任务外或他人在途区域的问题报告证据及依赖，不擅自代修。

重跑受影响调用路径、测试与项目规定的完整门禁。清理本次插桩、子进程和隔离资源，在迁移记录中补症状、根因、目标差异、修法及实际结果；尚有失败时不能标记阶段完成。
