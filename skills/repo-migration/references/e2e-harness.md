# 迁移验证装置

先查看项目现有集成、浏览器和进程验证入口。迁移只补当前行为证明的缺口，不因“端到端”建立一套平行体系；适用范围和运行命令由目标项目决定。

## 隔离与真实接缝

- 每个并行测试单元拥有独立数据、账号、缓存或工作目录；优先使用项目已有隔离方式，建立和清理都有明确所有者。
- 数据库或队列确为被测路径的一部分时，按既有装置和真实迁移链准备隔离资源；没有相关依赖的项目不创建它们。
- 真实外部服务可使用协议匹配、行为可编程的本地替身；覆盖本次相关的成功、错误、延迟、取消及畸形响应，避免测试间共享脚本状态。
- 使用实际应用入口和装配路径，不能为了通过而绕过待验证的内部边界。替换发生在哪一层、哪些真实契约未被验证须写明。
- 请求录制或诊断输出仅保留必要信息，脱敏凭证与用户数据。资源清理仅限本次创建并拥有的隔离资源，不能操作共享数据区。

## 行为与断言迁移

1. 先核实旧用例是否有效、是否受共享状态或偶发失败影响；旧断言与实现冲突时按目标与证据裁决，不任选一方当规格。
2. 保留行为继续验证相同的可观察契约；有效期望值来自已确认规则或样例，不能从新实现反推。
3. 显式准备种子事实，记录数据和协议形态的必要适配；装置改变不应暗中降低断言强度。
4. 有意行为变化关联需求依据、消费者影响及新验收；被移除测试注明原覆盖去向或不再需要的原因。
5. 有资金、任务或状态一致性语义时，核对实际不变量与完成条件，而不只断言请求成功；无此语义时不引入台账或后台结算装置。

同一输入对新旧实现做差分可作为补充证据，但不能替代对时序、权限和副作用的明确验收，也不能把旧缺陷自动认定为必须保留。

## 运行形态与资源清理

项目存在开发与构建产物两种真实入口，且迁移影响装配或运行条件时，分别验证相关启动、关键路径和退出行为。使用实际构建与启动脚本，不假定所有项目都提供相同探针、端口或退出契约。

检查静态资源、依赖解析、配置与清理在各形态下一致符合目标。子进程、订阅、临时服务与数据由创建者清理；测试异常也要有终止和清理路径。

## 真实环境检查

需要真实凭证、可能付费或修改共享环境时，先核对明确授权与项目操作约束。只执行本次相关检查；不复制共享凭证、克隆生产数据或创建默认付费门禁。

替身验证与真实上游验证分别报告。缺少权限、凭证或预算时说明未验证的契约；本次要求的真实验收未执行时该项保持未完成，非相关真实检查不成为无条件交付门槛。

需要系统性验证方案或装置确有缺口时，可参考可用的 `verify-harness`；没有它仍按以上隔离、行为和资源清理要求补足当前路径，不必安装另一技能。
