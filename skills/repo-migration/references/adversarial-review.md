# 迁移独立审查

审查是否保留已确认行为、实现获准变化，并覆盖测试未发现的契约与生命周期偏差。旧实现是比较证据，不能凌驾于明确目标。

## 安排与输入

目标或数据迁移方案风险高时在实施前审查；契约、权限、并发和资源密集的实施单元分别审查，低风险机械批次可合并。验证装置首次承担关键路径时也应核对它是否绕开真实接缝。

使用当前宿主可用的独立会话或子代理，默认继承模型；审查者只读且不实现代码。无独立能力时报告缺口，不能把自查当作满足项目明确要求的独立审查。

提供：

- 最终 diff、对应旧实现与必要调用上下文。
- 用户目标、项目约束、已确认保留行为及有意差异。
- 行为与测试迁移矩阵，装置适配记录。
- 已执行检查的结果和仍未验证的风险。

允许审查者沿真实调用链取证，不强迫其仅凭被裁剪的实现片段判断。

## 审查任务

> 对照目标与基线检查行为映射。寻找错误反馈、边界、权限、事件次数、副作用、取消、清理、持久化和消费者切换中的偏差。每项发现给出位置、触发条件、旧行为、目标及实际新行为，附可验证证据。区分缺陷、获准差异和待核实疑点，不因新旧不同就自动判错，也不为交付发现而编造问题。

检查断言变动的目标依据、旧覆盖的去向，以及装置是否保留了相关观察能力。记录未被审查的范围，找不到问题时说明实际检查面。

## 处置与复查

先执行适用验证再审查，修正后运行受影响检查及项目要求的完整门禁。每项发现由实现侧复现、修复或附证据驳回；有意差异引用已确认目标，不能事后补一句解释替代需求依据。

明确要求多轮 PR 审查时可使用 `pr-review-loop`；缺少该技能时按问题、修正和复查证据继续。未经授权不发布外部评论、推送或合并。要求的验证或独立审查未完成时，如实报告未完成条件。
