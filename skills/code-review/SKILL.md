# 代码审查

判断代码是否实现目标、是否引入可证实的问题，以及是否符合仍适用的仓库约束。分别保留需求与行为、规范与结构两个维度的结论；其中一项通过不能替另一项作结论。没有有效发现是合法结果。

## 1. 固定对象与范围

先读目标仓库 AGENTS，查看 Git 状态，确认用户要求审查的是工作区、暂存区、某段提交、PR，还是指定模块。复用对话中已有的范围和基准；只有歧义会改变审查对象时才询问。

记录实际基准、被审版本和文件范围。工作区要包含范围内未跟踪文件；暂存区按 index 内容审，不能拿磁盘上的后续修改替代。指定模块可以直接审当前内容，不因没有 diff、远端或 Git 历史就停止。具体取证方法见 [范围、版本与报告](references/scope-and-report.md)。

读相关调用方、被调用方、类型、配置和测试，核实变更影响。普通 diff 审查关注此次引入、加重或新暴露的问题；旧问题只有与本次结论有关时才单独注明。用户要求模块审计时可覆盖该模块现状，不自动扩大为整仓重构。

## 2. 明确两类依据

- **需求与行为**：本次用户目标、已确认规则、适用规格和实际消费方契约。检查遗漏、错误实现和未经要求新增的行为。代码与现有测试用于核实现状，不能单独证明目标正确。
- **规范与结构**：AGENTS、CONTRIBUTING、CODING_STANDARDS、适用 ADR、架构边界和实际工具配置。明确违反仍适用规则的发现需引用依据；类型断言、重复代码、文件长度或新抽象本身不是缺陷。

规格缺失时说明需求维度的核实限制，继续检查能够确认的逻辑、契约和质量问题；不强制先安装工单工具或补写规格。目标与旧文档冲突时核实本次已授权的变化，不让旧约束否定新目标，也不由审查者擅自重定目标。

## 3. 组织独立审查与核实发现

主 agent 默认创建两个全新上下文的只读子 agent 独立审查：一路侧重需求与行为，另一路侧重规范与结构及相关风险。两路都检查基本正确性，可以报告任一维度的问题。范围局部且已确认不改变行为、契约或关键风险的低风险小改动可只派一路，仍由全新上下文子 agent 覆盖两个维度，并说明单路依据；不能只按文件数或改动行数降为单路。

每次派发新建子 agent，默认继承当前模型，同时显式关闭父对话继承；不复用实现者或已有审查会话。主 agent 提供统一事实包，首轮不传实现者解释、预设 finding 或其他审查结论，子 agent 独立取证且不再委派。上下文选项、事实包和能力受限时的处理见 [全新上下文独立审查](references/scope-and-report.md#全新上下文独立审查)。

按 [审查准则](references/review-criteria.md) 选择与实际改动相关的维度：结果与错误路径、根因、数据与类型边界、状态与资源、安全、测试、UI、性能和结构成本。无需每次填满清单或要求固定数量的问题。

每个候选先问：输入或状态如何到达这里，发生什么错误，影响谁，依据是什么？沿真实调用链验证条件，必要时读 diff 以外的上下文。不能用“可能为空”“或许有竞态”“应该抽象”代替证据。

区分仓库硬约束、已证实缺陷、具体维护成本和个人偏好。结构建议说明现有复杂度造成的实际成本及可操作的简化方向；不为假设扩展要求增加层次或大改。工具已经可靠覆盖的格式、命名等机械检查不重复逐条报告；门禁失效或实际失败则保留为证据。

主 agent 收齐各路回报后去重，核实触发条件、调用链、证据与严重程度，再形成结论；不能直接转述子 agent 的判断。多个审查者同意只是核实信号，不按票数裁决，单路发现也按相同门槛核实。

## 4. 验证关键判断

优先复用项目已有的定向检查，记录命令及结果；只读审查不自动跑完整流水线。运行可能写入数据、缓存或生成文件的检查时，使用合适的临时目录或隔离副本，保持受审源文件、index 和 Git refs 原样。真实外部服务、共享数据、付费或发布动作遵循本次授权。

验证应检查目标行为和实际消费路径。测试全绿、构建通过和审查者自述都不能代替对 finding 的核实。不能运行时给静态路径和限制，不声称实测。推测尚未取得足够证据时列为待核实问题，不包装成确定缺陷。

审查结束前核对范围内版本是否变化。发生变化时重新检查受影响结论；无法取得新版本则明确本次结论的版本边界，不能沿用旧结论宣称当前代码已通过。

## 5. 交付结论

按两个维度汇总经过核实的发现，同一问题可合并并标注两类依据。每条包括严重程度、准确位置、触发条件、具体后果、证据与可操作的修复方向。严重程度取决于后果，维护性启发式和个人偏好不能直接升级为阻断。

简要列出对象与版本、实际审查路数及单路依据或委派限制、两个维度的实际结论、已执行验证和未验证项。无有效发现时直接说明无发现；对象缺失、范围为空和验证受阻分别说明，不把它们写成已经通过。报告例子见 [范围、版本与报告](references/scope-and-report.md)。

默认交付审查报告，不直接修改代码。用户另有明确修复授权时按范围处理；需要多轮审查、修复与复查可用 `pr-review-loop`，缺少它时也可基于明确发现做有限复查。审查请求本身不授权 commit、push、回写外部评论、合并或部署。
