# 飞书项目进度

将真实项目工作组织成“页面或业务入口 → 可独立跟踪的子功能”，通过 lark-cli 增量维护飞书任务表。管理进度不自动授权代码实现、后端接入、消息通知或部署。

## 确定目标与操作范围

- 优先复用本次请求或当前会话中，用户已指定且唯一的任务表链接。没有链接时先询问“请提供要管理的飞书任务表链接”，在目标明确前不进行远端写入；可继续独立检查代码。
- 多个目标无法消歧时请用户选择。技能文件不保存真实链接、Base token、表 ID、记录 ID 或人员 ID，也不跨项目沿用历史目标。
- 用户明确要求新建时，先确定是已有 Base 内建表还是新建 Base，并取得必要名称和目标容器；不因缺少链接而自行创建替代表。
- 区分本次要做的事情：代码盘点、任务拆分或重组、进度同步、只读汇报。已有授权内的写入直接完成，不重复确认；仅要求查看时不顺带改表。

飞书操作前读取当前环境的 `lark-shared` 和 `lark-base`；可用 `lark-cli skills read lark-shared`、`lark-cli skills read lark-base` 获取与 CLI 匹配的说明。已经读过则复用。创建表、操作字段和视图、增量写入时按需读取 [CLI 工作流](references/lark-cli-workflow.md)。

## 从当前代码拆分任务

盘点时先遵守仓库指令并读取 `git status --short`。核对路由、页面装配、业务组件、数据来源、用户操作及相关测试；以实现为准，不从目录名或说明文档直接推断完成情况。

- 一个页面作为一级分组，一条记录对应一个有明确结果、可单独跟踪的子功能。例如模型详情可拆为“详情资料与能力”“价格与费用估算”“在线测试”，密钥页可拆为“列表”“创建”“吊销”。
- 粒度由实际交互决定，不照搬固定页面清单或任务数量。加载、失败、重试、取消等通常是所属功能的完成条件，不逐个建成任务。
- 区分真实数据接入、演示响应、静态展示和已完成的本地能力。搜索、收藏、图表、复制、费用计算等是否需要远端服务，应由现有产品行为决定。
- 共享接口或数据源只维护一套接入事实；其他页面的展示任务注明复用关系。需要跨页面的会话、访问保护、请求配置等归入公共能力。
- 保留任务的功能范围、已知依赖和可观察完成条件；接口路径、DTO、鉴权方式、错误码及支付渠道只引用已确认契约，未知内容记录为待确认。
- 将代码位置与实现证据保留在本地盘点中或按授权范围同步。写入飞书的内容应符合用户指定目的地和当前外发权限；不要把“管理进度”理解为任意源码或凭据的外发授权。

仅同步用户提供的进度时，不必重新扫描整个仓库；只有需要核实状态、查缺口或解决冲突时才检查相关实现。

## 适配任务表

先解析链接，再读取目标表字段、类型、选项、视图范围和现有记录。字段名称只作语义线索，不能据此猜测可写类型或关联结构。

| 信息 | 使用方式 |
| --- | --- |
| 子功能名称 | 复用现有任务名称或描述字段 |
| 页面或入口 | 复用页面、模块或分类字段；需要按页面组织且缺字段时再补充 |
| 进展、负责人 | 沿用现有状态选项和人员字段；默认值与用户维护结果优先 |
| 优先级、日期 | 复用已有表达；建议顺序与紧急程度分开，日期有依据才填 |
| 功能范围、阻塞项 | 写入合适的现有说明字段，不将“资料待确认”写成已证实的阻塞 |

能用页面字段分组时，直接采用“页面分组 → 子功能记录”。已有父子关联且用户希望沿用时再使用真实关联字段；普通分组不宣称为原生子记录，也不额外创建重复的页面总任务。

用户要求重组时可调整相应分组。修改视图先读当前配置，保留无关筛选、排序及可见列；结构调整只添加本次必需内容，不重建整张表。新建表优先使用最小必要字段，并沿用当前 CLI 的字段协议。

## 增量同步与进度判断

- 查询范围必须覆盖本次同步对象。指定视图的结果只代表该视图；需要整表去重时读取整表，直到 `has_more=false`，不能用前一页判断某任务不存在。
- 先按已有记录 ID、页面及子功能语义匹配；改名或拆分前先复用相应记录。只创建缺项、更新变化字段；多条候选无法确定时不批量覆盖。
- 用户维护的负责人、进展、日期、说明等保留，除非本次明确要求修改。新增任务使用用户指定负责人或表的默认值；不凭空分配人员。
- 不默认删除旧任务，也不因记录消失而自动补建。代码与表中范围不一致时标明差异，按本次任务处理；再次同步应能保持无重复。
- 新发现的未接入功能使用表中对应的未开始状态。用户明确报告完成可以作为进度依据；从代码推断完成则需要相应验收证据，演示数据、请求函数或本地测试通过不能单独证明真实服务完成。
- 如果用户报告与可见证据冲突，说明差异，不静默改写用户进度。阻塞记录说明实际阻塞原因及解除条件；尚未核实的资料需求保持待确认。
- 优先级可按依赖和用户流程提出建议，不将建议写成交付承诺；不因缺少截止日期就断言任务不紧急，也不虚构开始、预计或实际完成时间。

## 写入验收与交付

同表写入串行执行，单批遵守 CLI 限额。以明确成功响应或可靠回查确认结果，部分失败仅处理已确认失败项；超时或结果不明时先回查记录，避免重放创建。回查只能证明任务存在、无法归因到本轮创建时，单列“已确认存在，新增数量未确认”，不虚报写入数量。

遇到权限问题沿用原身份处理。遇到确认门禁或自动审批拒绝，按其要求处理，不静默追加确认参数或换路径重试。可继续完成已允许部分；需要用户授权时说明被拦截的具体动作和原因。

本轮写入结束后统一核对相关任务、页面归属及视图配置，并报告可证实的新增、更新、未变和失败数量。按表内状态口径汇总每页子任务；存在父任务时只将叶子记录计入完成率，状态未知时单列，不推算权重。只读汇报应明确查询范围；进度汇报区分“任务表已更新”和“业务功能已完成”。交付本次实际目标链接、主要分组或变化及未解决事项，避免输出人员凭据或完整业务数据。
