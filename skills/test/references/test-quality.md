# 质量与清理规则

清理对象由测试的逻辑和契约决定。先看被测调用、输入、期望来源与断言，再判断名称和代码形式。下面列的是问题及处置条件，不是按语法批量删除的规则。

| 问题 | 判断依据 | 处置 |
| --- | --- | --- |
| 恒真断言 | 同一稳定值与自身比较；无论生产逻辑如何都不会改变结论 | 删除无效断言；若原用例有明确行为目标，补有效断言 |
| 复述声明 | 常量等于声明值，或把静态对象复制一份比较；找不到独立规则 | 删除；若承载真实契约，保留约束或改测实际消费行为 |
| 自建数据自验 | 创建测试对象后检查其属性，未执行任何相关生产逻辑 | 删除；需要验证解析、转换等行为时通过真实入口改写 |
| 自证式期望 | 没有独立约束，只把被测函数的输出当正确答案，或复制算法且没有独立正确性依据 | 改用规格、人工结果、可信样例或有约束力的性质 |
| 只验证替身 | 本次要验证的逻辑被 mock 掉，结论完全来自替身设置 | 恢复真实目标逻辑后改写；无目标行为则删除 |
| 断言过松 | 错金额、错用户、漏结果或重复副作用仍满足当前断言 | 加入能区分目标错误的结果、错误或副作用断言 |
| 名实不符 | 名称声称保护的行为与实际调用或断言不一致 | 先依据需求、消费者和历史回归核实契约；断言有效则改名，名称所述契约有效而断言错误则改断言，未决时保留待查 |
| 内部实现耦合 | 行为相同的重构仍因私有步骤、结构或内部调用顺序失败 | 改为稳定入口上的行为验证 |
| 无独立价值的重复 | 规则、条件、结果和故障探测能力均重合 | 按下文重复项裁决选择保留位置，迁移独有保障后合并或删除副本 |
| 已退役契约 | 当前需求及消费者明确移除该行为，测试只维护旧实现 | 删除相关测试及仅为其存在的测试辅助代码 |
| 测试文件内死代码 | helper、导出等没有调用方或发现路径；遗留注释段已无有效说明用途 | 核对全仓引用、框架发现及动态调用后清理；共享辅助代码和有效契约说明不能仅凭局部无引用删除 |
| 长期停用 | skip 用例长期不执行，停用原因缺失或已过期 | 核实原因和当前契约，恢复执行并验证、确认无价值后删除，或保留有原因和跟踪项的隔离；未决项明确待核实原因 |
| 仅输出观测结果 | 只 log 观测或性能数据，没有可判失败的目标行为、阈值或独立不变量 | 有回归目标则补有效判定，否则按用途保留为采样工具或删除，不计作自动回归保障 |

## 重复项裁决

先比较规则、前置条件、边界、异常、时序和实际故障路径，确认哪些保障重合、哪些独有，再选择承载位置：

- 优先保留断言区分力强、有效场景完整且失败容易定位的版本，不按断言数量排名。不能为合并把不同故障原因揉成一个难定位的大测试。
- 保留真实 bug 的触发条件、关键断言和台账或 issue 引用。可将这些信息迁入保留用例；有引用不等于当前断言仍有效，也不要求保留原文件。
- 装配、信号传递或协议边界的重复候选，优先保留能触达真实 signal/wire 路径的版本。mock 用例若仍保护独立错误路径或边界，就不属于可直接删除的副本。
- 保障等效后，优先放在主题归属明确的文件，沿用项目组织方式，便于后续定位与维护。
- 删除前迁移另一份独有的断言、场景和回归信息，并运行保留用例。独有故障路径无法迁移或证明等效时，继续保留相应用例；记录每个被删项的覆盖去向。

## 大范围清理

全仓、跨模块或候选多到难以逐项追踪时采用以下流程；局部清理不必建立整仓台账。

1. **先建立运行基线。** 在目标执行环境核实运行时、PATH、依赖及实际测试命令，先排除命令缺失等环境失败，优先取得绿色基线。分别记录环境阻塞、原有真实失败及偶发失败，不能把它们当作无效用例的证据。无法全绿时，说明可验证范围；受影响范围无法验证的删除暂缓，不要求顺手修复无关缺陷。有覆盖率门禁时同步采集基线及余量。
2. **分区扫描，先列候选。** 按行为主题、目录或共享设施划分范围，记录每区扫描状态和共享依赖。在可用且获准委派时可并行扫描，统一提供本表、重复项裁决和候选记录要求；扫描结论先列为候选，不能直接作为批量删除指令。
3. **统一裁决并核实。** 跨分区归并重复簇，逐项记录目标行为、契约依据、问题类别、建议处置、保留或替代位置及待核实项。抽检高风险候选和保留项来校准口径；每个实际删除项仍须有依据，不能以抽检代替。涉及历史回归、共享设施或真实调用链的争议，回到实现与契约核实，证据不足则保留。
4. **分批修改与验证。** 依据主文件“运行与证据”的批次和门禁要求执行，使失败能定位到具体批次。覆盖率门禁失败时核查独立边界或错误路径是否丢失，补有效保障或撤回相关删除，不为补数字恢复空转用例或弱化门禁。
5. **汇总可追溯证据。** 大范围任务将清理报告按项目约定落盘，汇总分区完成情况、各项处置及覆盖去向、实际命令与结果、覆盖率变化、原有失败和未执行项。沿用已有报告位置，不机械创建另一套长期台账。

## 防止误删

- 字面量不等于恒真。`expect(limit).toBe(20)` 可探测值改变，其价值取决于独立契约；不能与 `expect(limit).toBe(limit)` 混为一谈。
- 同一函数出现在断言两侧不自动构成自证。幂等、可逆等性质可以来自独立契约；需判断关系本身能否排除相关错误，并结合具体算例确认完整行为。
- 同一行被不同输入覆盖，不等于测试重复。正常路径、临界值、错误恢复、并发时序和历史回归可能捕获不同缺陷。
- 真实 bug 的回归不会因长期全绿而失效；查证它保护的故障路径及当前契约。
- 外部调用参数、禁止副作用、协议值、错误类型和不变量可以直接断言。精确文案或结构是否重要，也由消费方契约决定。
- 快照可以保护稳定输出。需要确认其中哪些变化有业务意义，避免只因快照大就删除，或未经核对批量更新。
- 新的上层测试存在，不自动证明旧单测可删。先确认旧用例的独立边界和故障风险已被覆盖；不能只看新测试名称或覆盖率。
- 慢、失败、偶发失败可能暴露真实问题。先区分实现缺陷、时序、污染、环境和退役契约；不得通过移除测试掩盖未解决失败。

## 清理证据

每项改写、合并或删除给出简短理由。重复项指出保留位置；替换项指出对应行为与新入口；退役项指出契约移除依据。小范围可以直接列在交付说明中，不机械创建长期文档或整仓矩阵。

检查删除后仍保留必要场景和错误探测能力，移除仅由已删除测试使用的 fixture、mock 和导入。共享辅助设施先核对其他引用，不扩大到无关生产重构。

运行相关测试及项目要求的门禁，比较实际结果；采集了覆盖率再报告变化。测试通过或行覆盖率不变，都不能单独证明行为保障没有丢失。证据不足时保留该测试并说明待核实原因，不为减少数量强行删除。
