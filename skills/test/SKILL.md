# 测试设计与质量

把真实契约转成能发现错误的用例。每个测试都应能说明：保护什么行为、期望从哪里来、哪种错误会让它失败。写测试和清理测试使用同一套质量标准。

## 确定任务与边界

先读目标仓库的 AGENTS、实际测试命令与配置、相关实现和邻近用例，核对已有修改与测试基线。沿用项目运行时、框架、测试位置和门禁，不复制其他仓库的命令或覆盖率阈值。

- **设计或编写**：依据本次范围补足有效场景，不自动扫描或清理整个测试套件。
- **审查**：给出测试质量发现及依据；只要求审查时保持只读。
- **清理**：逐项选择保留、改写、合并或删除，遵循下文清理条件。

测试任务不自动授权修改产品行为、公共接口或门禁。发现真实实现缺陷时，已有修复授权按范围执行；否则报告复现和影响，不改断言迁就缺陷。契约不清时先核对调用方、历史回归和需求证据，文档没写不等于没有契约。

## 设计与编写

1. **确定独立预期。** 写清输入、前置状态、动作与可观察结果，包括必要的错误和副作用。预期来自需求、外部契约、人工算例或独立不变量；当前输出不能单独证明自己正确。
2. **选择能触达风险的入口。** 纯计算通过函数接口验证；交互通过用户操作验证；装配、存储和跨边界缺陷在能覆盖实际调用链的一层验证。选择最小充分层级，不用被提取的辅助函数替代真实故障路径，也不为普通单测另建装置。
3. **选有区分力的场景。** 按真实规则选择代表性输入、临界值、错误路径和状态转换。每个场景应对应不同的故障风险；不按实现分支、字段数量或覆盖率缺口机械生成镜像测试。
4. **执行真实逻辑，断言业务结果。** 名称表达条件和行为；使用具体输入和独立期望。断言应区分正确结果与有意义的错误，避免只检查非空、存在或未抛错就宣称行为正确。
5. **控制替身与非确定性。** 替身隔离适合的依赖边界，保留本次要验证的真实逻辑。等待异步结果，控制时间、随机源与共享状态，清理本次资源；不靠增加等待或重试掩盖缺陷。

设计场景、选断言或判断 mock 边界时，按需读 [用例设计与例子](references/test-design.md)。

## 审查与清理

对每个待处理测试回答：

- **目标行为被破坏时，它能失败吗？** 只考察它声称保护的目标，不要求一个测试捕获所有错误。必要时在隔离副本做局部故障验证，保留结果并清理临时改动；不强制引入 mutation 框架。
- **保持行为的内部重构后，它能继续通过吗？** 若依赖私有调用顺序、内部字段或中间结构，检查是否需要改成行为断言。
- **它还提供什么独立保障？** 比较输入边界、异常、时序、环境和历史回归，不能只凭行覆盖率重叠认定重复。

明确的清理对象包括恒真断言、仅复述声明且没有独立契约的常量或静态对象测试、只验证测试自建数据、无独立约束地用被测逻辑生成期望、锁死无契约内部细节、没有独立价值的重复用例，以及契约已明确移除的旧测试。

保护的行为仍有价值时优先改写；重叠场景可合并，但保留不同条件、断言与失败定位能力。只有确认没有独立保障、已有等效覆盖，或目标契约确已移除时才删除。给出简短理由与保留或替代覆盖的位置；证据不足的保留并说明未知。

常量、快照、mock 和调用次数都不自动构成删除理由。公共协议值、外部副作用和跨数据不变量可以是有效契约。失败、耗时或偶发失败的测试先诊断原因，不能直接当作无效测试删除。具体判定见 [质量与清理规则](references/test-quality.md)。

## 运行与证据

- 已知 bug 的回归先观察测试因目标缺陷失败，再确认获授权修复后通过；无法取得修复前证据时如实说明。
- 给已有正确行为补契约测试允许起初就绿，不为展示红灯制造产品缺陷。真实运行并核对结果，代码能编译不能代替行为验证。
- 从相关用例开始，按共享设施与公共边界的影响扩大范围；阶段或交付门禁遵循目标项目要求。不得通过 skip、弱化断言、缩窄覆盖率范围或降低阈值换绿。
- 报告实际命令、结果和适用的测试数；采集覆盖率时给真实数字，未采集时说明。清理任务另报改写、合并、删除的理由和覆盖去向；原有失败与未执行项保持可见。

## 与其他技能配合

- 本技能负责测试设计与质量。用户要求先测试后实现，或需要 bug 的失败到通过循环时，可用 `tdd`；缺少它时仍按本文取得回归证据。
- 系统性验证功能、跨进程交付物或建设验证装置时，可用 `verify-harness`。普通补测试不展开完整装置流程。
- 每个技能都可独立使用，不为调用本技能先安装其他技能。
