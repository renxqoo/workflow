# 集成缺陷定位

目标是把失败变成可复现的根因，再验证完整调用路径。定位动作与临时插桩仍遵循目标项目的代码、权限及工作区约束。

## 先确认失败形态

- 记录触发输入、运行形态、部分输出、等待位置及最后一个已确认的副作用。
- 对网络或流式问题区分未发出、对端未回应、数据已返回但未被消费。
- 运行时支持时采集挂起瞬间的栈、任务或进程信息；日志只保留定位所需内容，不能泄露凭证或用户数据。
- 比较单用例与相关组合运行，检查共享状态、并发顺序、连接池和缓存污染；不直接重复整仓测试来碰运气。
- 定位可临时缩小输入、收紧本地超时或减少路径；不能把这些改成门禁的默认掩盖措施。

## 缩小根因范围

沿真实调用链逐层验证输入输出，找到第一个违反契约的位置。怀疑运行时行为时创建最小独立复现，先排除测试自身的错误假设；只有必要且获准时才切换运行时或版本做交叉验证。

按症状选择核查项：

- 流式消费与背压可能让写入或变换等待下游读取；确认所有分支的消费和取消责任，不能看到等待就判定死锁。
- 重试、连接池和资源上限可能造成排队或重复副作用；核对负载与预算，不用降低负载掩盖问题。
- 开发与构建产物的模块解析、静态资源和依赖闭包可能不同；在实际失败形态复现。
- 取消、停机和晚到结果可能泄漏订阅或任务；验证完成和失败后都能释放资源。

这些是调查方向，不是预设修法。根据复现证据决定最小充分修复，不能直接套用过去的 workaround。

## 修复与复查

在授权范围内修复已证实根因并添加症状回归，取得修复前失败与修复后通过证据；取得不到时说明原因。根因落在任务外或他人在途区域时报告证据和依赖，不擅自改动。

重跑相关调用路径、受影响测试及项目要求的完整门禁。清理本次临时插桩与测试进程，按项目约定记录根因、修法及验证限制；不能只凭局部用例通过宣称系统恢复。
