# 跨模块与大型功能方案

在项目现有文档结构中记录下列相关内容；不涉及的项简述不适用原因，避免为模板编造契约、性能数字或数据模型。

## 目标与契约

- 当前行为、用户目标及验收时可观察的结果。
- 调用方、输入输出、错误与取消语义、事件及副作用时序。
- 保留、修正与移除的行为，及每项变化的需求依据。
- 范围之外的内容、已存在的归属和本次不处理的后果。

## 风险与结构

- 受影响模块、公共接口、依赖方向和复用现有实现的方式。
- 涉及时记录权限隔离、共享状态、并发交错、重试、超时及清理责任。
- 有项目要求或测量证据时写明性能、数据量和资源预算；未知数字先测量或标明待确认，不能伪装成硬约束。
- 区分用户决定、项目既有约束、代理实现选择与真正阻塞的待确认问题。

## 实施与迁移

- 按业务切片安排实施及验证，先完成风险最高的最小真实路径。
- 替换内部实现时列受影响调用方、测试和文档，完成迁移后再删除旧接口。
- 外部契约或持久化变化说明获准的过渡方式、回退条件及清理时点；没有迁移授权时不能先破坏现有数据或消费者。
- 大型功能记录存量行为映射、关键安全回归与切片试运行结果；若整体任务是行为等价的架构迁移，再使用 `repo-migration`，缺少该技能时仍可按这些要点实施。

## 测试与验收

- 每项目标对应独立期望值、行为测试入口和验收证据。
- 列相关边界、异常、取消及权限路径，不为无关输入扩大测试范围。
- 区分修改中相关检查、阶段完整门禁与获准的真实环境检查。
- 列独立审查输入及触发条件、无法执行检查的处理方式。

按项目约定记录状态与实现结果。实现推翻决定时同步更新依据；文档数量、命名、提交格式和检查命令由项目决定，不从模板生成第二套政策。
