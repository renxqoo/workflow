# 轻量方案

用于局部、可逆且风险低的功能或修复。方案可在工作说明、现有任务文档或项目认可的提交正文中表达，不要求新建文件或等待形式化批准；必需的用户决策仍须得到实际答复。

需要说清：

- 目标行为与可观察的完成条件。
- 本次改动位置、影响面与范围边界。
- 已有契约或项目约束，以及代理自行选择的实现方式。
- 回归或行为验证入口，阶段与交付时的项目检查。

例如一项表单修复，应指出什么输入产生何种反馈、影响哪个入口、如何复现及验证；不要将“新增一个函数”当作完成条件。

沿用项目既有记录方式，不把方案写成代码注释，不把等待否决当成操作授权。只有发现新的契约、权限、异步生命周期或存量数据风险时才增加方案细节；升级后的内容按 [跨模块方案](design-b.md) 补充，不重复起草已确认需求。
