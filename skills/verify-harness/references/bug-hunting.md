# 有依据的缺陷假设与测试分层

仅用于用户要求的系统性验证范围，不要求日常补单测先完成整份巡检。先核实契约和已有覆盖，再选能增加证据的风险。

## 程序

1. 列本次功能的外部入口、目标状态、共享资源、信任边界和上下游契约。
2. 选择下面相关风险。每个候选给依据、触发条件和可观察后果；没有证据支持的猜测先调查，不为类别或数量造用例。
3. 查现有测试是否已经覆盖，再分给最便宜且足以覆盖真实风险的一层。
4. 写独立期望值和必要断言，使用已有测试设施和公开接口。对已证实 bug 保留缺陷失败证据，非 bug 契约测试可直接通过，不需故意引入错误。
5. 达到本次覆盖目标或预算上限后停止，记录实际发现、未验证假设和环境限制。发现缺陷不自动建票/修产品；按本次用户范围处理，可选建议其他已有流程。

## 风险与层次

| 风险 | 典型问题 | 合适验证层 |
| --- | --- | --- |
| 输入 | 合法边界、缺字段/null/空串、类型、数值、编码、畸形结构 | 纯解析/规则用表驱动单测；协议装配差异才上集成 |
| 状态 | 非法转换、重复事件、终态、守恒量、部分失败 | 单测状态机；跨资源事务/持久化一致性用集成或旅程 |
| 并发/时序 | 双击、晚订阅、乱序、取消、重试与共享可变状态 | 可控交错单测足够则单测；真进程/中间件时序才上旅程 |
| 资源 | 监听/定时器/文件/进程清理、失败释放、退出和恢复 | 单测生命周期或真实资源集成；崩溃注入仅在隔离授权内 |
| 权限/安全 | 无/过期凭证、越权、注入、重放、泄露 | 纯校验单测；真实认证/中间件链路需要集成/旅程 |
| 契约 | 词表、序列化、时区/金额单位、分页、版本/产物差异 | 静态类型/单测覆盖规则；跨边界和消费者形态用旅程 |

风险不代表一定有 bug。金额精度、兼容策略或终态规范以目标契约为准，不硬套某种实现或数据类型。性能/压测需要独立的目标和测量依据，不拿行为旅程随意定义时延门槛。

## 用例质量

- 断言目标行为、边界、错误反馈和适用副作用，不只断言“没报错”。
- 值来自独立契约或人工算例；不能复制静态声明、测试自己构造的对象或用被测逻辑求期望。
- 一个假设可以被现有用例覆盖，也可以无需新增用例；只在增加可辨别证据时加测试。
- bug 回归先确认旧行为因目标缺陷失败。无法访问旧实现、运行受阻等情况要说明证据性质，不能将环境错误当复现。
- 未能构造触发时报告“未证实”，不把全部怀疑发布成 issue，也不无限跑随机循环。
