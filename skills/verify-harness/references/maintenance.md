# 验证装置维护

先确认本次授权的功能/目录范围。维护装置不等于授权修产品、改 CI 或发布工单/PR；只修允许的装置脚本与文档。产品缺陷报告真实证据，不在文档里把坏行为写成正确行为。

## 诊断与检查

1. 找已有装置文档、功能地图、入口命令与产物；没有地图可在本次范围内补真实映射，不能推断没有地图就没有测试。
2. 核对地图索引、实际用例和近期变更，识别死路径、重复条目和确有源码依据的遗漏。
3. 按功能读取真实代码和契约，可用只读子 agent 分工，缺少子 agent 时串行。读取结果给位置、行为和可执行配方；不让多个 agent 驱动共享实例。
4. 在条件和权限允许时，对本次受影响功能运行代表性消费路径；全面审计请求才按范围覆盖所有功能，不自动扩大成全量回归。
5. 每次尝试保持健康检查、资源所有权、失败清理与证据保留。无法运行的项标为未验证，不因源码看起来一致称为活跑通过。

## 分类

| 类型 | 判据 | 动作 |
| --- | --- | --- |
| 文档漂移 | 当前契约与实现合理，地图过时 | 在允许范围内修地图并核对真实命令 |
| 装置缺口 | 功能符合契约，但驱动/fixture/清理错误 | 用已有架构修装置，运行受影响路径证明 |
| 环境阻塞 | 资源、权限、凭证或服务不可用 | 说明限制，不编造 env/接口，不改产品迎合坏环境 |
| 产品缺陷 | 应用违反目标契约 | 给症状、复现和后果；无修复授权时报告，不自动建票 |

环境失败不能算产品失败，当前产品行为也不能自动算规范。先核对本次要求、明确契约、真实配置，再决定是哪一类。

允许的装置改动后有界重试，重复同样阻塞且无新证据时停止扩展。不得通过改文档、skip 或移出默认门将失败变绿。

## 收口

- **clean**：声明范围已核实，必要运行完成，无改动；记录实际覆盖。
- **changed**：有已验证的装置/地图修正，按目标项目 AGENTS、脚本和 CI 完成适用检查。
- **incomplete**：部分覆盖或运行未完成，给阻塞、证据和下一步；不能称全绿。

是否保存运行笔记、提交、推送或发 PR 依本次授权及项目约定，不自动执行。后续维护仅在用户要求或已有授权内安排，不自行增加定时任务。
