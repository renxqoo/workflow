# 装置文档骨架模板

生成 `verify/SKILL.md`（或仓库约定位置）时复制此骨架填充。规则：
**没有占位符残留**——每个 `<...>` 都要换成访谈找到的真实值；
写不出的节如实写「本仓库无此面」而不是留空或编造。

```markdown
# <仓库> 验证装置

改动面映射表在 features/README.md；「改了 X 该跑什么」先查它。

## Deliverables

主：<主要交付物及一句话（是什么 + 消费方是谁）>
次：<其余交付物；没有写无>

## Launch

<精确命令>。就绪信号：<机器可判定的信号>。
拆除：<teardown 命令>。
并行：<可并行（隔离手段：端口 X / 数据目录 Y / schema Z）/ 拒绝双开（原因）>。

依赖假体：
- <fake-a>：<位置>，模仿 <什么边界>，启动方式 <命令>

（库交付物的 Launch = 消费方式装配：入口函数怎么拿、依赖怎么给。）

## Doctor

一条只读检查：<命令>。判定：<什么输出算健康>。
任何时候驱动前先跑；出过怪事后必须重跑。

## Drive

按交付物分节，全部用本仓库真实句柄：

### <交付物 a>
<驱动配方：真实选择子 / 命令 / 端点 / 入口函数。不是示例语法。>

## Evidence

- 证明标准：捕「消费方动作 + 结果态」，副作用单独断言；
- 存放点：<目录>；
- 证据在 cleanup 后必须仍存活于该位置。

## Cleanup

只杀自己启动的（按进程句柄/PID 文件，不按进程名）。
清理实例与临时态，**永不清理证据**。

## 三门

| 门 | 内容 | 跑法 | 进默认门禁 |
| --- | --- | --- | --- |
| 默认门 | <确定性旅程清单> | <命令> | 是，按改动面选择性跑 |
| 冒烟门 | <双形态冒烟：源码形态 vs 构建/打包产物形态> | <命令> | 手动/发布前 |
| real 门 | <真凭证场景清单> | <命令> | 否，opt-in |
```

## 写作纪律

- 命令逐字可执行——agent 会照抄，示例语法（`your-app-here`）是事故源；
- 继承既有分门时如实记录（「本仓库已有 smoke/real 双配置，装置继承之」），
  不重造门禁结构；
- 降级形态（in-process 装配、假依赖替身）显式标注，不冒充全链验证；
- 改动面映射表是装置的操作界面，单独放 `features/README.md` 顶部；
- 装置文档自身走仓库文档纪律（不写版本叙事，只描述当前行为）。

## 改动面映射表格式

放 `features/README.md` 顶部：

```markdown
| 改动面 | 必跑旅程 | 证明什么 |
| --- | --- | --- |
| <packages/billing 结算路径> | <billing-recovery/journey> | <崩溃后账仍平：对账差为零> |
| <renderer 会话舞台组件> | <ui-e2e 四场景> | <流式渲染/排队/结算消费全链正确> |
```

条目来自既有旅程的语义归纳，不是文件名罗列。没有映射的旅程写「全量兜底」。
