# 装置文档内容模板

沿用目标仓库已有约定；没有约定时可以用 `verify/`。以下是待填结构，输出时只保留适用节，替换成真实命令和前置。无法核实/执行的项明确标记，不能编造可用装置。

```markdown
# 项目验证装置

## 交付物与覆盖
本次交付物、消费方、目标契约；改动面映射的真实链接。

## 启动与就绪
真实启动/装配命令、环境与种子、依赖假体、就绪信号、隔离/串行约束。

## 健康检查
只读检查命令、判定范围与失败信号。

## 驱动
已有测试或消费路径的精确命令、前置、结果断言和必要副作用。

## 证据
项目实际证据目录；版本/旅程/断言、脱敏方法和留存方式。

## 清理
本次持有资源的具体清理命令，失败退出同样执行；证据继续保留。

## 现有运行规则
现有默认、冒烟或真实依赖检查的适用条件、选择性入口和覆盖限制。
本次未执行项与所缺资源/授权。
```

## 填写纪律

- 复用已有脚本、fixture、框架、隔离和拆除，不迁移原测试或改语义。
- 改动面 → 现有用例/跑法 → 证明内容 → 前置/限制的映射是操作入口，放在已有索引或方便发现的位置。
- 不强行凑三门，不把双形态冒烟降为手动，也不把真实调用变成默认/nightly。
- 测试入口、CI、定时任务和门禁修改需要本次明确授权；文档只记录已存在规则和已获授权的变化。
- 真实服务运行需明确授权、资源与隔离条件；没有条件时如实说明未覆盖。
- 文档有真实命令且按其运行成功后才称已验证；只完成设计或静态整理时称草稿/未实跑。
- 记录实际结果而非笼统全绿；验证要求由目标 AGENTS、脚本、配置和 CI 决定。
