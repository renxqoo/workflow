# 功能地图与改动面映射

沿用已有验证文档和索引位置；无约定时可使用 `verify/features/`。地图是现有装置的入口，不是另一个框架。

## 索引

顶部放改动面映射：

```markdown
| 改动面 | 现有用例/旅程与精确跑法 | 证明内容 | 前置/未覆盖 |
| --- | --- | --- | --- |
| 会话恢复 | 项目实际命令与用例 | 过期会话拒绝，恢复后状态一致 | 隔离假上游；未验证真服务 |
```

条目从真实代码与用例语义归纳，不只列文件名；多个改动面可复用同一用例。没有可靠选择性跑入口时说明当前需跑的最小现有集合，不凭空编过滤参数或自动改测试入口/CI。

后面列本次有价值的功能文档及其验证行为，保持链接和实际文件一致。

## 功能条目

形式按项目约定，覆盖四类信息即可，不要求固定英文标题或严格 H2 数量：

1. 消费方可感的功能、目标契约与本次覆盖边界。
2. 消费入口和前置：配置、隔离状态、fixture、假体及资源权限。
3. 精确驱动方式：真实命令/稳定选择子 → 可断言结果 → 适用副作用。
4. 限制和陷阱：哪些环境未验证、并行约束、怎样清理与保留证据。

命令来自实际脚本并核实可执行；不要把本机私有路径、示例端点或未定义 env 写成仓库事实。无法运行时标“未验证/缺前置”，不能用其他路径冒充覆盖。

## 维护

本次功能变更确实影响驱动或契约且允许编辑文档时，同步更新受影响地图。不自动审计所有功能或要求额外 PR。产品坏了报告缺陷，不能让地图追随缺陷改成“正确行为”；必要维护流程见 [维护流程](maintenance.md)。
